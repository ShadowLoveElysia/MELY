## 一般ユーザー向けの使い方

1. [GitHub Releases](https://github.com/ShadowLoveElysia/MELY/releases) から Windows x64 インストーラー `MELY-<version>-windows-x64-setup.exe` またはポータブル版 `MELY-<version>-windows-x64-portable.zip` をダウンロードします。一般ユーザーは Source code アーカイブをダウンロードする必要はありません。
2. インストール版はインストーラーを実行します。ポータブル版はアーカイブを完全に展開してから `MELY.exe` をダブルクリックします。WebView2 が見つからないと表示された場合は、Microsoft Edge WebView2 Runtime をインストールしてください。
3. `.pmx` または `.pmd` モデル、もしくはモデルとテクスチャを含む ZIP ファイルを読み込みます。必要に応じてダンスモーションまたは表情の `.vmd` を追加します。
4. ダンストラックと表情トラックは、対応するデータを読み込んだ場合だけ表示され、未読込のトラックは場所を取りません。各トラックを個別に調整し、組み合わせたポーズが決まったら読み込まれている全トラックをロックします。
5. ソリッドブロックモードまたは Ethereal Hologram ワイヤーフレームモードを選択し、目標高さ、サンプリング間隔、マテリアル方式を設定してから投影を生成します。
6. 3D プレビュー、材料一覧、階層別建築ガイドを確認し、対象エディションに応じて `.litematic`、`.schem`、`.mcstructure` または `.mcfunction` ビヘイビアーパックを書き出します。

> パッケージ化されたインストール版とポータブル版には、Node.js、Rust、Visual Studio Build Tools は必要ありません。以降の環境設定、クイック起動、ビルド、開発コマンドは、ソースから MELY を実行するユーザーまたは開発参加者向けです。

MELY は、Minecraft の建築クリエイター向けの MMD モデル変換・工程計画ツールです。

名称の `M` は Minecraft、`ELY` は ELYSIA に由来します。PMX、PMD キャラクターモデルと VMD モーションを、プレビュー、ポーズ固定、実際の建築に使える Minecraft 像および投影ファイルへ変換することを目的としています。

MELY は現在、Minecraft Java Edition 1.20.1 のブロックレジストリを主な対象としつつ、Java Edition と Bedrock Edition の両方に対応する書き出し機能を提供します。

## 主な機能

- `.pmx`、`.pmd` モデル、ZIP モデルパッケージ、および関連テクスチャの読み込み。
- VMD のボーンモーションと表情モーフを独立トラックに分離し、実際に読み込まれたトラックだけを表示。
- ダンストラックと表情トラックを個別に再生、一時停止、スクラブ、1 フレームずつ調整、ロックし、プレビューと生成時に選択フレームを合成。
- ダンストラックがある場合は Space キーでダンスを操作し、ない場合は表情トラックを操作。
- GPU によるリアルタイムアニメーション描画と、フレームのロックまたはボクセル化時のみ行う CPU スキニングスナップショット生成。
- モデルボーンの手動調整と、軽量な MELY Pose JSON の読み込み・書き出し。
- ソリッドブロックのボクセル化と Ethereal Hologram ワイヤーフレーム生成モード。
- 縦向きのエンドロッドと独立した白色のガラス板による疎なキャラクター輪郭の表現と、独立した内部投影密度の調整。
- アルファしきい値、三角形とボクセルボックスの交差判定、薄い表面の保存、現在ポーズのサンプリング。
- CIEDE2000 色差マッチング、肌色保護、顔のディテール強化、マテリアルブラックリスト、テーマ別パレット。
- 発光マテリアルのマッピング、夜間プレビュー、調整可能なディザリング強度。
- 材料一覧、シュルカーボックスとチェストの計画、Web 階層別建築ガイド、プロジェクトの自動分割。
- `.litematic`、`.schem`、`.mcstructure`、`.mcfunction` ビヘイビアーパックの書き出し。
- 2,032/4,064 層向けの任意解除、多段階リスク表示、試行可能な生成・出力フロー。
- 簡体中国語、English、日本語のインターフェース。

## 動作環境

### 必須環境

現在のソース版とクイック起動スクリプトには以下が必要です。

- 64 ビット版 Windows 10 または Windows 11。
- **Node.js 20 以降**。
- Node.js に付属する `npm`。
- WebGL 2 に対応したモダンブラウザー。Microsoft Edge または Google Chrome を推奨します。
- 初回の依存関係インストール時に npm パッケージレジストリへアクセスできること。

16 GB 以上のメモリとディスクリート GPU を推奨します。目標高さを上げる、ソリッド充填を使用する、または大きな高解像度テクスチャを扱うと、リソース使用量が大幅に増えます。

Node.js をインストールした後、CMD で確認します。

```bat
node --version
npm --version
```

`node --version` に `v20` 以降が表示される必要があります。

### デスクトップ開発モード

Tauri デスクトップアプリをソースからビルドして起動する場合は、さらに以下が必要です。

- Rust stable MSVC ツールチェーンと Cargo。
- Microsoft Visual Studio Build Tools。
- Visual Studio Installer の **C++ によるデスクトップ開発** ワークロード。
- Microsoft Edge WebView2 Runtime。

これらの追加コンポーネントは、デスクトップ開発とパッケージ作成にのみ必要です。Web モードを強制する場合、Rust と Visual Studio Build Tools は不要です。

## クイック起動

プロジェクトディレクトリで次のファイルをダブルクリックします。

```text
起動 MELY.bat
```

次のファイルを直接実行することもできます。

```bat
MELY.bat
```

ランチャーは次の順序で動作します。

1. パッケージ済みまたはインストール済みの `MELY.exe` を探し、見つかった場合はそれを起動します。
2. EXE がなく、デスクトップ開発環境が完全な場合は、Tauri 開発版を自動的にコンパイルして起動します。
3. デスクトップ開発環境が不完全な場合は、自動的に Web モードへ切り替えます。
4. Web モードでは、`dist` がない、またはソースより古いかを確認します。
5. 依存関係が未インストールの場合、初回起動時に `npm ci` を自動実行します。
6. TypeScript チェックと Vite プロダクションビルドを実行し、ローカルサーバーを起動してブラウザーを開きます。

既定のアドレスは次のとおりです。

```text
http://127.0.0.1:4173/
```

ポートが使用中の場合、ランチャーは後続の空きポートを試し、最終的なアドレスをウィンドウに表示します。

### 起動オプション

自動ビルド付き Web モードを強制します。

```bat
MELY.bat --web
```

Web アプリを強制的に再ビルドします。

```bat
MELY.bat --web --force-build
```

ブラウザーを開かずにサーバーを起動します。

```bat
MELY.bat --web --no-open
```

Tauri デスクトップ開発モードを強制します。

```bat
MELY.bat --dev
```

Rust、Cargo、または C++ Build Tools がない場合、`--dev` は Web モードへフォールバックせず、エラーを表示します。

## 自動ビルドの動作

現在のランチャーは MELY を自動的にビルドして起動できますが、モードごとに動作が異なります。

| モード | 依存関係の自動インストール | 自動ビルド | 自動起動 |
| --- | --- | --- | --- |
| `MELY.bat --web` | 依存関係がない場合に `npm ci` を実行 | ビルドがない、またはソースより古い場合に `build:web` を実行 | ローカル Web サーバーを起動し、ブラウザーを開く |
| `MELY.bat --dev` | なし | Tauri と Vite の開発ビルド | デスクトップ開発ウィンドウを開く |
| `MELY.bat` | 検出結果に応じる | 選択されたモードに応じる | EXE、デスクトップ開発、Web モードの順で優先 |
| パッケージ済み `MELY.exe` | 不要 | 不要 | デスクトップアプリを直接起動 |

デスクトップ開発版の自動起動は、リリース用インストーラーの生成とは異なります。正式なデスクトップパッケージを手動でビルドするには、次を実行します。

```bat
npm ci
npm run build:desktop
```

## Windows ワンクリックパッケージ作成

Node.js 20 以降、Rust stable MSVC、Visual Studio 2022 C++ Build Tools、Windows 10/11 SDK がインストールされた PC で次をダブルクリックします。

```text
構築 MELY.bat
```

英語のエントリポイントは `Build MELY.bat` です。ビルダーは次を自動実行します。

1. Node.js、Cargo/Rust、MSVC x64 リンカー、完全な Windows SDK を確認します。
2. `npm ci`、型チェック、全テスト、Web プロダクションビルドを実行します。
3. Tauri で Windows x64 アプリ本体と NSIS インストーラーを生成します。
4. ポータブル ZIP、インストーラー、SHA-256 チェックサムファイルを `release/` に配置します。

既定ファイル名には `src/version/version.json` のバージョンが使用されます。

```text
MELY-<version>-windows-x64-portable.zip
MELY-<version>-windows-x64-setup.exe
MELY-<version>-windows-x64-SHA256SUMS.txt
```

パッケージ化されたポータブル版とインストール版に Node.js は必要ありません。

## GitHub 自動リリース

プロジェクトには 2 つの Windows リリースワークフローがあります。

- `.github/workflows/dev-release.yml`: `main` ブランチに新しいコミットが追加されると、テストとパッケージ作成を行い、`dev-latest` タグをそのコミットへ移動し、**MELY Development Build** プレリリース内の固定名アセットを置き換えます。Actions ページから手動で実行することもできます。
- `.github/workflows/release.yml`: 正式な GitHub Release が公開されると、後続の `main` ではなく、その Release に紐付くタグをチェックアウトします。ビルド成功後、ポータブル ZIP、NSIS インストーラー、チェックサムファイルを同じ Release の Assets にアップロードします。

正式リリースの推奨手順は次のとおりです。

1. `src/version/version.json` のみを更新します。デスクトップビルドと Windows リリースのエントリーポイントは Cargo 用の派生バージョンフィールドを自動同期します。すぐに反映したい場合だけ `npm run version:sync` を手動実行してください。
2. 変更をコミットし、そのコミットにタグを作成します。タグ名はリリース方針に合わせて自由に設定できます。
3. そのタグから正式な GitHub Release を作成し、公開します。
4. **Windows Release Assets** ワークフローがアセットのアップロードを完了するまで待ちます。

Release のタイトルとタグ名は、アプリケーション内部のバージョンと一致する必要はありません。アセットのファイル名には `src/version/version.json` のアプリケーションバージョンが使用されます。GitHub リポジトリで Immutable Releases が有効な場合、公開済み Release にアセットを追加または置換できません。現在の「公開後にビルド」フローを使用するには、この機能を無効にしてください。

既存の Release を再ビルドする場合は、Actions ページから **Windows Release Assets** を手動実行し、その Release のタグ名を入力します。

## 基本ワークフロー

1. PMX、PMD、テクスチャを含むモデルファイルまたは ZIP パッケージを MELY へドラッグします。
2. 必要に応じてダンスモーション VMD、表情 VMD、またはボーンとモーフの両方を含む VMD を読み込みます。
3. MELY は読み込まれたトラックだけを表示します。ダンスと表情を個別に再生またはスクラブし、目的のモーションフレームと表情フレームを組み合わせます。
4. 読み込まれている全トラックをそれぞれロックし、組み合わせたポーズをボクセル化と投影生成に使用します。
5. ソリッドモードまたはホログラムワイヤーフレームモードを選択し、目標高さ、サンプリング間隔、マテリアル方式を設定します。
6. 投影を生成し、3D プレビュー、材料一覧、階層別建築ガイドを確認します。
7. 対象プラットフォームに応じて Litematica、Schematic、Bedrock Structure、またはコマンドビヘイビアーパックを書き出します。

VMD のリアルタイムプレビューでは、ボーン、モーフ、IK を既定で計算します。再生とタイムライン操作の遅延をできる限り抑えるため、高コストな物理シミュレーションは有効化していません。

## 高さの互換性

- 正確な Profile が Java バージョン情報を提供します。一覧の各バージョンで best-effort の生成と出力を試せます。Java 1.20.1 はリポジトリ内の形式テスト対象ですが、十分にテストされていない版は既知のシリアライザーへフォールバックする場合があり、互換性問題や軽微な不具合があり得ます。リポジトリ内の NBT 再読込は、Litematica や WorldEdit による実ツール受入試験ではありません。
- 既定の推奨キャラクター高さは 320 ブロックで、バニラワールドの上下限界内に設置用の余裕を確保します。
- 既定のディメンション範囲は選択した正確な Profile から取得します。Java 1.20.1 は `Y=-64..319`（384 層）です。
- 利用者は 2,032 層の拡張を任意に解除し、生成と出力を試せます。対象ワールドには通常、正確なバージョンとディメンションに合う第三者製データパックが必要です。既定の宣言は `min_y=-1024, height=2032` で、導入したパックに合わせて編集できます。
- 4,064 層の実験状態は 2,032 の解除後、解除・環境表示・今回の出力確認を経て有効化できます。基準設定は `min_y=-2032, height=4064`（設置可能 `Y=-2032..2031`）で、「バニラ 4096」対応ではありません。このフローは十分にテストされておらず、互換性問題や軽微な不具合があり得ます。
- 高さ上限を超える投影を通常のワールドに読み込むと、上部の欠落、ゲームの遅延、Mod のクラッシュ、セーブデータの破損が発生する可能性があります。

MELY は第三者製高さデータパックの作成、同梱、ダウンロード、導入、検証、保証を行いません。提供元、ライセンス、正確なバージョン、`pack_format`、`dimension_type`、`min_y`、`height` を確認し、ワールドのコピーで境界設置、チャンク再読み込み、実際の貼り付けツールを試すことを推奨します。これらの表示は生成や出力の試行を妨げません。互換性問題はコミュニティへ報告してください。

## よくある質問

### Node.js が見つからない

Node.js 20 以降をインストールし、CMD を開き直すか、ランチャーを再度ダブルクリックしてください。解決しない場合は、`where node.exe` を実行して Windows が Node.js を検出できるか確認します。

### デスクトップウィンドウではなくブラウザーが開いた理由

自動モードは、Rust、Cargo、Tauri 依存関係、または Microsoft C++ Build Tools が利用できない場合に Web モードへ切り替えます。これによって主要な変換機能が損なわれることはありません。

### 初回起動が遅い理由

初回の Web 起動時には、npm 依存関係のダウンロード、TypeScript チェック、Vite プロダクションビルドが必要な場合があります。以降の起動では、最新の状態である間は `dist` を再利用します。

### 大きなモデルのプレビューまたは生成が遅い理由

目標高さを下げる、サンプリング間隔を広げる、ホログラムワイヤーフレームモードを優先する、または高解像度テクスチャの数を減らすことができます。フレームロック後の CPU スキニングとボクセル化は、引き続き高負荷な計算処理です。
